\section{Interface de inspeção e relatórios}
\label{sec:interface}
O acesso interativo implementado utiliza Swagger UI, hospedado pela API síncrona. Seu seletor carrega os contratos das duas variantes e permite enviar o mesmo evento, consultar o código HTTP e examinar a resposta. Para testar idempotência, o usuário preserva identificador, instante e conteúdo no JSON reenviado. A consulta de registro utiliza a API síncrona. Isso atende à inspeção manual; não equivale a um produto de operação com autenticação ou a um sistema de uso corporativo.

A avaliação quantitativa utiliza k6, executor e analisadores. Seus relatórios offline identificam coleta, variante, unidade e janela, distinguem HTTP de conclusão e sinalizam ausência de evidência. Esses instrumentos realizam UC05 e UC06 sem depender de uma tela web. Demonstrações interativas posteriores são separadas da campanha e não alteram seus resultados.

\subsection{Evoluções propostas de interface}
Os wireframes anteriores descreviam um formulário próprio, acompanhamento visual de backlog e comparação de indicadores. Não foram usados como evidência de implementação. O formulário dedicado continua fora da entrega: exigiria controle de identidade em reenvios e apresentação distinta de aceite e persistência. Uma interface de operação também precisaria de autenticação, controle das ações de falha e tratamento de dados sensíveis. Essas evoluções são retomadas nos trabalhos futuros.
